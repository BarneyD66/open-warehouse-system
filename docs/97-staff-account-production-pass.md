# 生产级员工账号治理增强

## 本轮目标

员工账号体系需要从“能登录”推进到生产可控：管理员可邀请员工、激活账号、禁用账号、审批角色变更，同时接口和审计不能泄露密码哈希等敏感字段。

## 已完成

- 员工账号存储层已替换为干净中文实现，保留 Postgres/本地文件双存储、密码哈希、登录认证、自助改密、禁用账号和角色变更审批。
- 新员工支持无初始密码创建为“已邀请”状态；填写初始密码时直接激活为“可登录”状态。
- 已禁用或已邀请账号不会因为普通保存资料而自动恢复登录，只有管理员输入新密码时才会激活。
- 员工账号 API 统一返回脱敏账号视图，不再把 `passwordHash` 返回到前端。
- 员工账号相关审计日志也改为记录脱敏后的账号状态，避免敏感字段进入审计记录。
- 接口错误和操作摘要改为清晰中文，方便管理员排查。

## 产品策略

当前方案兼容“现在只有一个员工”的试运营状态，也支持后续新增运营、仓库、财务、管理员等正式账号。生产环境仍可保留 `STAFF_WHITELIST_JSON` 作为紧急兜底，但日常账号治理应优先使用员工管理后台。
