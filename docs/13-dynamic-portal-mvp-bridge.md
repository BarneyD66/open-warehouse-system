# 动态客户门户 MVP 衔接记录

## 市场团队交接

市场团队把调研结果交给产品经理后，本轮需求从“做一个好看的客户门户”升级为“客户提交过的内容要能在门户里看到”。这代表网站正在从展示型原型向 MVP 过渡。

关键需求：

- 提交询盘后，客户/运营能在门户看到询盘待跟进。
- 提交入库预报后，客户/运营能在门户看到货件状态。
- 缺附件、缺追踪号要转成待办。
- 移动端要能直接扫读待办和货件，避免横向表格。

## 产品经理拆解

1. `/portal` 保持服务端页面，读取本地提交记录。
2. 指标由真实记录计算，而不是静态假数据。
3. 待办由规则生成：
   - 入库预报无附件：待补资料。
   - 入库预报无追踪号：待补追踪号。
   - 询盘记录：询盘待跟进。
4. 我的货件读取真实 ASN 记录。
5. 最近提交用于验证数据链路。

## 已完成

- `/portal` 设置为动态路由。
- 接入 `getSubmissions()` 读取 `.local-data/submissions.json`。
- 页面指标动态展示：
  - 待补资料
  - 待补追踪号
  - 询盘待跟进
  - 近期提交
- 待办列表由真实提交记录生成。
- 我的货件列表由真实入库预报生成。
- 最近提交列表展示询盘与入库预报。
- 待补资料和待补追踪号已接入 `/supplement?asn=...`。

## 验证

- `npm run lint` 通过。
- `npm run build` 通过。
- Next.js 构建中 `/portal` 显示为动态路由。
- Playwright 验证 `/portal` 能看到真实记录 `ASN-UK-202605-2742` 或 `INQ-202605-2000`。
- 桌面端和 390px 移动端无页面级横向滚动。
