# 采购到货差异闭环

## 本次补齐内容

对标马帮类 WMS 的入库作业，本次把采购/补货到货从“扫码签收、上架”继续补成“差异登记、客户确认、运营跟进”的闭环。

## 支持的差异类型

- 少货
- 多货
- 破损
- 错 SKU
- 缺标签
- 其他差异

## 仓库端流程

1. 员工进入仓库作业台。
2. 在扫码作业台选择“采购到货”。
3. 扫描采购到货单号、追踪号、SKU 或库位。
4. 如果发现少货、多货、破损、错 SKU 或缺标签，在同一面板登记到货差异。
5. 系统会把采购到货单状态改为“异常”，并写入差异记录。
6. 系统自动生成客户可见工单，状态为“待客户确认”。

## 客户端可见结果

客户在工作台工单区可以看到“入库差异”工单，内容包括：

- 采购到货单号
- 客户编号
- 供应商
- SKU
- 预计数量、实收数量、影响数量
- 仓库填写的差异说明
- 照片或凭证链接

客户后续可以在工单内回复处理意见，例如确认补发、接受少货、要求赔付或提供新标签。

## 运营端可见结果

运营后台的采购到货列表会显示差异摘要和关联工单号。运营也可以在“客户自助工单处理队列”中接单、回复客户、标记待补充或关闭。

## 差异处理闭环

运营确认客户回复、补发、赔付或内部处理结果后，可以在采购到货列表里直接处理差异：

- 标记已处理：差异状态变为已解决，系统会给客户工单追加处理完成消息，并关闭客户工单。
- 忽略：用于确认无需继续处理的轻微差异，系统同样会给客户工单追加说明并关闭工单。

处理后系统会重新计算采购到货单状态。如果没有其他未处理差异，采购单会按签收和上架进度恢复为“部分签收”“已签收”或“已上架”。

## 完成状态保护

采购到货单存在未处理差异时，不会被误判为正常上架完成。只有预计数量完成上架且没有未处理差异时，才会进入“已上架”状态。

## 审计与报表

差异登记会写入操作日志，审计日志导出已修复为中文标签，方便后续按客户、入库单、操作人和时间追溯。
