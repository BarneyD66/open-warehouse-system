# 退货确认通知与运营提醒

## 目标

退货质检后，系统不能只记录状态，还要主动提醒应该处理的人：客户需要确认处理方式时提醒客户，客户确认后提醒运营继续处理。

## 已落地能力

- 客户通知中心会识别退货单是否进入到仓、质检、维修或异常状态。
- 如果客户还没有确认处理方式，会显示“退货处理方式待确认”。
- 客户确认重新上架、维修、报废或转寄后，运营待办中心会显示“客户已确认退货处理方式”。
- 运营提醒中会显示客户编号、RMA 单号、确认方式和客户备注。
- 客户确认类运营提醒按高优先级展示，避免遗漏。
- 原有工单回复、物流异常、账单和库存提醒继续保留。

## 使用路径

1. 仓库扫码到仓或运营进入退货质检。
2. 客户工作台待办中心出现退货处理方式确认提醒。
3. 客户在退货页提交处理方式。
4. 运营后台待办中心出现客户确认提醒。
5. 运营按确认结果推进上架、维修、报废或转寄。

## 后续可增强

- 为退货确认提醒配置 SLA 超时升级。
- 将确认提醒推送到企业微信、飞书或邮件。
- 按员工角色分配退货处理负责人。
