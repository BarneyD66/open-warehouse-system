# 164 生产错误处理闭环

## 背景

上一轮已建立生产错误事件台账，并接入生产日志、系统告警和健康检查。本轮继续把“看得到错误”推进到“能直接处理错误”，让运营和老板在生产日志检索里即可确认或关闭生产错误事件。

## 已完成

- 新增生产错误处理 API：
  - `GET /api/ops/system/errors/[id]` 查看单条生产错误事件。
  - `PATCH /api/ops/system/errors/[id]` 支持确认、关闭、重开。
  - 接入员工权限校验、接口限流和审计日志。
- 新增审计动作 `production_error_update`，审计导出和审计面板均显示为“生产错误处理”。
- 生产日志接口调整：
  - 生产错误日志的关联编号固定为错误事件编号。
  - 业务关联编号保留在详情中，避免前端处理时拿错 ID。
- 运营后台“生产日志检索”增强：
  - 生产错误行显示“确认”和“关闭”按钮。
  - 处理后自动刷新日志列表。
  - 成功/失败都有中文提示。

## 验收点

- 生产错误不需要只通过系统告警间接处理。
- 运营能在日志检索里直接确认或关闭错误。
- 每次处理都会进入审计日志。
- 关闭后底层错误事件状态更新，后续健康检查不再把该错误作为开放错误统计。
