# 212 集成探测告警归类优化

## 本轮目标

继续补齐生产运维和平台 API 闭环，让集成探测失败不只停留在探测页面，而能进入对应业务域的系统告警。

## 已完成

- 系统告警中心按集成探测类型归类来源：
  - 承运商探测归入物流；
  - 平台订单 API 探测归入平台；
  - 对象存储和安全扫描归入资料文件；
  - 通知投递归入通知；
  - 报表投递归入任务。
- 对平台、承运商、存储、安全扫描的探测失败提高到关键告警。
- 告警详情补充缺失环境变量、建议动作和探测人。
- 告警跳转指向对应运营模块，方便员工直接处理。

## 产品价值

- 平台/承运商 API 的凭证、endpoint、权限问题会进入统一告警中心。
- 老板和运营不需要逐个页面找异常，能在总控台看到关键生产风险。
- 后续真实 API 接入后，联调失败、配置缺失和权限错误更容易闭环跟进。

## 下一步建议

- 将平台探测失败自动生成待办，并支持指派给运营或技术负责人。
- 对重复失败的集成探测增加升级规则，例如连续三次失败提升为关键告警。
