# 130. 员工账号敏感操作二次确认补强

## 本轮范围

- 员工账号新增、重置密码、禁用账号、角色变更审批统一纳入“权限配置”敏感动作。
- 如果当前角色在权限矩阵中开启“敏感操作需要二次确认”，后端要求确认内容必须等于目标员工账号。
- 正式员工账号治理面板补充禁用原因、二次确认输入。
- 角色变更审批卡片补充单独的二次确认输入，并在审批成功后清空该员工确认值。

## 生产化价值

- 管理员误禁用、误重置、误审批角色的风险更低。
- 审计日志能保留禁用原因和权限审批结果。
- 和现有库存调整、客户暂停、账单锁定的二次确认模型保持一致。

## 验证

- `npm run lint`：通过。
- `npm run build`：通过。

## 剩余建议

- 后续可接入邮件/飞书邀请链接，让“已邀请”员工自行设置初始密码。
- 可在员工管理中增加按状态、角色、最近登录时间筛选。
