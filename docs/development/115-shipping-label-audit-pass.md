# 115 出库物流面单审计闭环

## 本轮目标

补齐出库物流面单关键动作的审计留痕，让运营、仓库和老板视角都能查到“谁在什么时候做了什么”。

## 已落地

- 新增审计动作 `outbound_shipping_label_update`。
- `/api/ops/outbounds/[id]/shipping` 已覆盖以下动作的审计：
  - 运费试算
  - 生成承运商面单
  - 取消/作废承运商面单
  - 转为内部/人工面单
  - 平台发货追踪号回传重试
  - 实际运费核对
- 每条审计记录包含：
  - 操作人
  - 出库单号
  - 客户编号
  - 操作前出库单快照
  - 操作后结果
  - 失败原因或补充备注

## 产品价值

- 面单生成、取消、失败、改人工、平台回传这些动作都进入审计链路。
- 后续接 Royal Mail、DPD、Evri 真实 API 后，接口返回的网关结果也会一起进入审计。
- 老板/管理员可以从审计后台追踪物流关键动作，不再只依赖出库单当前状态。
