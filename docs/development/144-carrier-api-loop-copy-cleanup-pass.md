# 144 承运商 API 闭环与发货面板中文化

## 本轮目标

继续对标马帮的物流闭环能力，把真实承运商下单、面单、取消、轨迹回传、签收证明和异常处理这条链路梳理成运营能直接使用的版本。

## 已完成

- 清理 `carrierGateway` 的真实承运商接口提示，保留 Royal Mail、DPD、Evri、人工渠道的网关匹配、买面单、取消面单、轨迹/POD 主动同步能力。
- 清理运营发货接口的中文错误和审计摘要，覆盖试算运费、生成面单、取消面单、转人工面单、重试平台发货回传、主动同步承运商轨迹/POD、核对实际运费。
- 清理承运商 webhook 入口，保留 HMAC/密钥校验、10 分钟重放窗口、重复事件幂等、按出库单/追踪号/承运商运单号匹配订单、派送异常、签收证明归档。
- 清理运营后台发货面板 UI 文案，员工可以直接看到面单状态、网关模式、失败原因、平台回传状态、最新轨迹和运费差异。

## 使用方式

- 运营后台在出库单发货区域选择承运商服务，先试算，再生成面单。
- 真实渠道需要在物流渠道中选择 `sandbox` 或 `live`，并配置对应环境变量，例如 `ROYAL_MAIL_API_KEY`、`ROYAL_MAIL_LIVE_LABEL_URL`、`DPD_SANDBOX_TRACKING_URL`。
- 承运商 webhook 可回传到 `/api/webhooks/carriers/{provider}`，生产环境必须配置 `CARRIER_WEBHOOK_SECRET` 或 `{PROVIDER}_WEBHOOK_SECRET`。

## 剩余事项

- 接入各承运商正式账号后，需要按对方真实字段补适配器映射。
- 真实 PDF/ZPL 下载、赔付材料上传和派送失败改派规则还可以继续做更细的供应商级配置。
