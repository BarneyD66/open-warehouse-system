# 134 补资料上传归入正式文件安全链路

## 本轮目标

将客户“入库预报补资料”里的附件上传，从旧的本地临时写入方式，统一到正式资料库和文件安全基础设施，避免绕过对象存储、病毒扫描、资料台账和预览权限。

## 已完成

- `POST /api/supplements` 继续支持客户补充追踪号、附件名称和备注。
- multipart 文件上传改为调用 `addDocument`，统一写入 `warehouse_documents` / 本地资料库。
- 上传资料自动关联：
  - 客户编号：当前登录客户
  - 关联类型：`inbound`
  - 关联单号：入库预报编号
  - 文件分类：`packing_list`
  - 上传角色：客户
- 复用正式文件链路：
  - 文件大小限制
  - 基础安全扫描
  - 外部病毒扫描 webhook
  - 对象存储网关 / 数据库 / 本地兜底
  - 后续下载与预览权限
- 增加补资料接口限流，降低被恶意批量上传的风险。
- 将该接口的用户可见错误文案恢复为中文。

## 产品价值

客户补充装箱单、箱唛、采购单、尾程资料时，不再只是记录一个文件名，而是形成可审计、可下载、可预览、可归档的正式资料记录。运营和老板后续查某个入库预报时，可以通过资料中心看到文件来源、上传人、扫描状态和关联单据。

## 后续建议

- 在客户入库预报详情页直接展示已上传资料卡片。
- 在运营入库详情页展示资料预览入口和缺资料提醒。
- 将补资料成功后的系统通知推送给运营待办。
