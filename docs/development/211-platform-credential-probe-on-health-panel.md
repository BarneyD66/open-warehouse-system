# 211 平台凭证探测接入健康看板

## 本轮目标

继续补齐平台订单 API 同步的生产化细节，把平台连接的凭证、endpoint 和权限探测能力放到运营日常看板中。

## 已完成

- 平台同步健康看板的每个 API 店铺连接新增“执行探测”按钮。
- 店铺卡片展示最近一次凭证探测状态：未探测、探测通过、配置缺失、探测失败。
- 店铺卡片展示最近探测时间和返回消息，方便定位 token、orders endpoint、base url 或权限问题。
- 复用现有 `/api/ops/integrations/probes` 和上线体检中的 `platform:{connectionId}` 集成项，不新增重复接口。
- 运营后台把最新平台探测记录传入平台同步健康看板。

## 产品价值

- 接真实 Amazon、TikTok Shop、Shopify、eBay API 前，运营能先确认凭证和地址是否可用。
- 同步失败时可以区分“平台没新订单”“字段校验失败”和“凭证/接口不可用”。
- 真实平台订单同步更接近日常可维护、可审计、可排障的生产闭环。

## 下一步建议

- 平台探测失败后自动生成系统告警。
- 在平台连接配置页增加必填项提示和环境变量配置指引。
