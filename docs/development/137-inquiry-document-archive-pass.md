# 137 询盘附件正式归档到资料中心

## 本轮目标

询盘表单本来有附件上传入口，但文件没有真正进入资料中心。客户容易误以为已经提交完整资料，运营后台却只能看到询盘文字。此轮将询盘附件接入正式文件链路。

## 已完成

- 资料模型新增 `inquiry` 关联类型。
- 客户资料上传接口和运营资料上传接口均允许 `inquiry` 类型资料。
- `/api/inquiries` 支持 multipart 表单：
  - 保持原有 JSON 提交兼容。
  - 创建询盘后，将附件保存到资料中心。
  - 登录客户归属到自己的客户编号。
  - 未登录公开询盘归属到 `PUBLIC_LEAD`。
- 询盘附件复用正式文件安全能力：
  - 文件大小限制。
  - 基础安全扫描。
  - 外部病毒扫描 webhook。
  - 对象存储 / 数据库 / 本地兜底。
  - 资料中心检索、预览、下载和安全状态展示。
- 询盘前端改为 FormData 提交，附件和资料清单会一起提交。
- 成功页显示附件归档结果，失败时保留询盘成功并提示哪些附件未归档。

## 产品价值

客户在报价前上传的 SKU 表、装箱单、FBA 标签、产品图片等资料，现在能被运营在资料中心直接检索和下载，报价审核从“看备注”升级为“看真实文件”。这更接近马帮类系统对客户资料留痕、审核和后续履约衔接的要求。

## 后续建议

- 在运营询盘卡片上显示该询盘的资料数量。
- 对带附件的询盘自动提高跟进优先级。
- 将公开询盘转正式客户后，支持把 `PUBLIC_LEAD` 资料批量迁移到客户编号。
