# 163 生产错误事件台账

## 背景

生产日志检索中心已经能聚合系统告警、任务队列、Webhook、自动化和审计记录。本轮继续补齐生产运维能力：把关键 API 的未预期异常写入独立错误事件台账，并进入生产日志、系统告警和健康检查。

## 已完成

- 新增 `productionErrorStore`：
  - 支持本地 JSON 和 Postgres 持久化。
  - 记录错误编号、严重级别、来源、路由、方法、错误信息、堆栈、请求编号、IP 线索、User-Agent、操作人和处理状态。
  - 支持查询开放/已确认/已解决错误。
  - 支持更新错误处理状态。
- `/api/ops/system/logs` 新增“生产错误”来源：
  - 可按关键词、级别、来源筛选。
  - 可导出 CSV。
- 系统告警中心新增生产错误告警：
  - 开放错误进入告警列表。
  - 严重错误按 critical 处理。
  - 告警确认、搁置、关闭会同步更新底层错误事件状态。
- 生产健康检查新增“生产错误事件”检查项和开放错误数量指标。
- `/api/ops/mabang-modules` 接入自动异常捕获：
  - 未预期异常返回错误编号。
  - 自动写入生产错误台账。
  - Next.js redirect/not-found 框架信号会重新抛出，不误记为 500。

## 验收点

- 关键 API 出现未预期异常时，运营能拿到 `errorId`。
- 老板或运维可以在“生产日志检索”按错误编号、路由、操作人搜索。
- 系统告警和生产健康检查能反映开放生产错误。
- 处理告警后，错误事件状态同步更新，健康检查不再一直显示同一条开放错误。
