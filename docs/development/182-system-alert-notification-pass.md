# Pass 182 - 系统/API 告警通知联动

## 背景

Pass 181 已经让 API、Webhook、自动任务异常进入系统告警。本轮继续把这些告警接入员工待办和通知投递链路，减少人工盯盘。

## 本轮完成

- 扩展 `getStaffNotifications()`。
  - 新增可选 `systemAlerts` 输入。
  - 未处理的严重/警告系统告警会转成员工待办。
  - 严重告警默认使用站内信 + 邮件渠道，普通告警默认站内信。

- 接入运营后台。
  - 运营页已有的 `systemAlerts` 会传入员工待办中心。
  - API 失败、Webhook 卡住、自动化失败等问题会同时出现在告警中心和待办中心。

- 接入通知生成定时任务。
  - `/api/ops/notifications/generate-due` 会读取系统告警。
  - 生成统计增加系统告警数量和严重系统告警数量。
  - 导出/审计日志记录中加入系统告警计数。

## 验证

- `npm run lint`
- `npm run build`

两项均通过。

## 后续优先级

1. 在通知订阅界面增加更明确的“系统/API 告警”说明。
2. 给关键接口失败增加负责人分派建议。
3. 继续补客户侧物流证据下载和费用差异说明。
