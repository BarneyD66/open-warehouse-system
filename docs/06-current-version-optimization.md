# 当前版本优化方向

## 产品经理结论

结合竞品对标与移动端客户操作要求，当前版本不能只追求视觉高级感，还要证明三件事：

- 客户能相信：英国仓的入库、库存、订单、退货、FBA、费用和异常都是可视、可追溯的。
- 仓库能执行：后台不是展示看板，而是扫码、收货、上架、拣货、复核、出库的作业系统雏形。
- 手机能处理：客户在移动端能快速查状态、确认异常、补交资料、看账单，不必等回到电脑前。

## 本轮已补齐

- 官网新增价格与计费说明，明确仓储费、入库处理费、出库操作费、退货/FBA 增值费对应的业务事件。
- 官网新增集成边界说明，明确当前版本先支持 CSV/Excel/手工录入，后续再接 Shopify、平台 API 和承运商接口。
- 官网新增仓库扫码执行模块，展示收货、差异、上架、复核出库的任务链路。
- 官网新增质量门禁展示，把库存、费用、异常、移动端四条红线放到页面上。
- 客户工作台新增三条流程入口：创建入库预报、导入出库订单、确认退货方案。
- 仓库后台新增 PDA / Mobile Scan 预览，用于表达后续仓内移动作业方向。

## 下一轮建议

- 把官网拆成正式路由：首页、服务项目、价格与计费、操作流程、帮助中心、联系我们。
- 把“提交合作询盘”和“创建入库预报”做成真实表单。
- 把客户门户的三条流程做成可点击多步原型。
- 把仓库后台的扫码作业做成独立移动视图。
- 开始设计基础数据层：客户、SKU、ASN、库存流水、订单、退货、FBA、计费事件。

## 本轮验收标准

- 页面保留高端可信的品牌感。
- 页面明确说明费用和集成边界。
- 页面能看到移动端客户操作。
- 页面能看到仓内扫码作业方向。
- 移动端 390px 宽度无页面级横向滚动。
- `npm run lint` 与 `npm run build` 必须通过。
