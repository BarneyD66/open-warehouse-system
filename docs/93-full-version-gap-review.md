# 完整版差距梳理

Date: 2026-06-17

## 当前判断

当前系统已经不是早期 MVP。客户注册登录、客户工作台、运营后台、仓库作业台、入库、出库、SKU、库存、库位、扫码、批量导入导出、打印、退货、账单、工单、报表、权限、审计和上线体检都已经有可操作闭环。

但如果按马帮类系统的完整生产能力来对标，当前仍属于“可日常试运营 / 可小团队使用”的阶段，距离完整版主要差在真实外部连接、深层 WMS 规则、财务实账和生产级治理。

## 已具备的关键能力

- 客户账号：自注册、登录、资料、公司信息、VAT、EORI、店铺资料、修改密码和重置密码。
- 员工账号：白名单登录、角色分流、权限矩阵、审计视图和上线风险提示。
- 客户工作台：待办、报价、入库、出库、库存、物流、账单、退货和工单。
- 运营后台：询盘、入库审核、出库推进、账单复核、资料中心、异常中心、报表和配置中心。
- 仓库作业：扫码收货、入库上架、库位维护、拣货、打包、交运、批量波次和打印。
- 库存管理：正式库存余额、库存流水、库存调整审批、批次/效期基础、盘点、补货和调拨基础。
- 物流管理：规则匹配、运费试算、面单追踪号 MVP、追踪节点回传、物流异常和承运商账单导入。
- 财务账单：费用规则、账单确认、付款提交、运营复核、月结锁账、利润/成本报表基础。
- 数据与上线：Postgres 持久化、健康检查、上线体检、中文导出和移动端适配基础。

## 离完整版还差什么

### P0：必须补齐，决定能否大规模正式使用

1. 真实承运商 API 闭环
   - 现在已有承运商配置、凭证引用、运费规则、面单 MVP 和账单导入。
   - 还缺真实 API 下单、真实 PDF/ZPL 面单获取、取消面单、重新买单、真实轨迹 webhook、派送失败自动工单、签收证明和赔付流。

2. 平台订单 API 同步
   - 现在已有平台连接、CSV 导入、字段映射、同步任务记录和沙箱预检。
   - 还缺 Amazon、TikTok Shop、Shopify、eBay 等真实 API 授权、增量拉单、订单取消同步、发货回传平台、同步失败重试和平台异常队列。

3. 生产级员工账号和权限后台
   - 现在生产建议使用 `STAFF_WHITELIST_JSON`，权限矩阵已有。
   - 还缺正式员工管理页、邀请/禁用员工、员工改密、二次验证、角色变更审批和敏感动作二次确认。

4. 文件基础设施
   - 现在文件可上传下载，Postgres 会保存文件内容。
   - 还缺对象存储、文件预览、病毒扫描、大文件上传、过期下载链接、发票/对账单正式文件归档。

### P1：需要补强，决定仓库效率和运营质量

1. 深层 WMS 规则
   - 还需要把库区、货架、库位、容量、混放规则、冻结库存、残次品库存、移库、盘盈盘亏审批、FIFO/FEFO、批次号、效期和序列号做成更强的规则化能力。

2. 出库波次和拣货策略
   - 现在有批量波次和拣货单。
   - 还需要按承运商、库区、SKU 热度、截单时间、订单类型自动组波次，并支持二次分拣、复核差异、称重校验和异常截单。

3. 费用和真实对账
   - 现在有费用规则、账单、承运商账单导入和利润报表。
   - 还需要仓租日/月计算、操作费自动生成、贴标/换箱/退货质检/超尺寸/燃油/偏远费完整落账、客户账期、付款核销和账单争议审批流。

4. 消息中心和 SLA 自动提醒
   - 现在有待办和工单。
   - 还需要站内信未读、邮件/短信/微信通知、SLA 到期提醒、超时升级、客户确认按钮和订阅配置。

### P2：增强体验和管理层决策

1. 报表中心产品化
   - 现在已有 SLA、异常、库存、库位、扫描、退货、利润等导出。
   - 还需要可视化筛选、保存视图、定时发送、指标钻取、客户维度利润、仓库效率和员工绩效。

2. 客户自助能力升级
   - 还需要客户自助下载签收证明、面单、费用明细、库存报表、出库明细、模板中心、异常确认和售后沟通沉淀。

3. 数据治理和运维
   - 还需要数据备份/恢复、错误监控、接口限流、导入任务队列、失败重试、生产日志检索和关键业务告警。

## 完整度估算

- 面向小团队试运营：约 80%。
- 面向真实客户日常使用：约 70%。
- 面向马帮级完整 ERP/WMS/OMS/物流系统：约 60%。

主要原因不是基础流程缺失，而是外部真实 API、生产权限、安全文件、自动化规则和财务实账还没完全沉到底。

## 建议开发顺序

1. 先做真实承运商闭环：Royal Mail 或 DPD 先接一个，从买单、面单、轨迹、异常到签收证明跑通。
2. 再做平台订单同步：先选 Shopify 或 TikTok Shop 作为首个 API，同步订单并把发货追踪号回传平台。
3. 补强 WMS 深层规则：库位容量、冻结/残次、移库、批次效期、FIFO/FEFO 和复核称重。
4. 做财务实账：承运商账单、操作费自动生成、客户月结、付款核销和账单争议审批。
5. 做消息和 SLA：站内信、未读、超时提醒、客户确认和异常升级。
6. 做生产级治理：员工后台、二次验证、对象存储、日志监控、备份恢复和上线告警。

## 最近一轮最值得推进

下一轮建议优先做“真实承运商 API 适配层”。理由是它能把当前的物流 MVP 变成真正发货闭环，也能带动面单、追踪、异常、账单和客户体验一起升级。

## 2026-06-18 推进状态

本轮已把“真实承运商 API 适配层”作为优先项落地，并同步补齐平台同步、员工治理、文件安全、财务自动入账、报表定时配置和生产运维入口。

已完成到代码层：

- 承运商：统一网关、沙箱/正式模式、凭证引用、真实面单失败保护、取消面单、轨迹 webhook、面单状态回写。
- 平台：统一平台订单同步网关、API 沙箱/正式拉单、出库单保留平台订单号、面单生成后发货追踪号回传。
- 员工：正式员工账号 Postgres 优先持久化、员工启用/禁用/改角色/重置密码 API、登录优先校验正式员工账号、登录限流。
- 文件：对象存储上传网关、基础安全扫描、文件预览接口、限时签名下载、可配置上传大小。
- 财务：自动生成出库基础费、出库 SKU 件数费和仓租草稿，月结争议复核后再付款核销。
- 消息：未读/已读、全部已读、通知订阅、SLA 超时升级和多渠道订阅配置。
- 报表：保存视图基础上新增定时报表配置，并补充员工绩效报表。
- 运维：管理员备份导出、任务队列失败重试、上线体检扩展对象存储/平台 API/正式员工/备份状态。
- WMS：普通入库上架、采购整单上架、采购扫码上架和移库审批已接入库位状态、容量、混放和特殊库位校验。

仍需外部条件：

- Royal Mail、DPD、Evri 的正式账号、测试环境和密钥。
- Amazon、TikTok Shop、Shopify、eBay 的店铺授权和 API 应用审批。
- 邮件/短信/微信通知供应商配置。
- 生产级病毒扫描服务和对象存储服务最终选型。
