# 开发路线图

## 第一阶段：产品蓝图与原型

目标：完成可讲清业务、可演示客户价值的第一版。

交付物：

- 市场调研结论。
- 竞品参考。
- MVP 功能清单。
- 官网与系统页面结构。
- 数据模型。
- 开发路线图。
- 可运行网站原型。

验收标准：

- 能用一页网站讲清“英国海外仓 + 中文客户门户 + 仓库后台”的定位。
- 能展示客户门户核心看板。
- 能展示仓库后台核心工作台。
- 能展示入库、库存、订单、退货、账单、异常的闭环。

## 第二阶段：MVP 基础工程

建议技术栈：

- 前端：Next.js + React + Tailwind。
- 后端：优先 FastAPI/Django 或 Laravel，取决于团队熟悉度。
- 数据库：PostgreSQL。
- 文件：对象存储，保存标签、装箱单、照片、合规文件。
- 权限：RBAC + customer_id 数据隔离。

基础模块：

- 登录、角色权限、客户隔离。
- 客户档案和 KYC。
- SKU 管理。
- 入库预报。
- 收货和上架。
- 库存余额和库存流水。

## 第三阶段：履约闭环

核心模块：

- 订单创建和批量导入。
- 库存校验和锁定。
- 拣货任务。
- 打包称重。
- 运单号录入。
- 出库确认。
- 出库扣库存。
- 客户端状态同步。

验收标准：

- 客户可以创建订单。
- 仓库可以拣货、打包、出库。
- 系统能更新库存和订单状态。
- 每个出库订单有操作日志。

## 第四阶段：退货、FBA 和异常

核心模块：

- 退货预报。
- 仓库收退。
- 质检拍照。
- 换标任务。
- 重新上架/销毁/转寄。
- FBA 中转单。
- FBA 贴标、换箱、打托。
- 异常中心。

验收标准：

- 退货能从到仓到处理完成。
- FBA 补仓能从库存锁定到出库。
- 异常可以关联 ASN、订单、退货、账单。

## 第五阶段：计费与账单

核心模块：

- 费率卡。
- ChargeEvent 计费事件。
- 入库费、仓储费、出库费、退货费、换标费、FBA 费。
- 月度账单。
- 账单导出。
- 付款凭证。
- 财务确认收款。

验收标准：

- 每一笔费用都能回溯到业务单据。
- 财务可以生成账单。
- 客户可以查看和下载账单。

## 第六阶段：集成与效率提升

建议顺序：

1. Shopify 订单 API。
2. Royal Mail 或 DPD 面单 API 单渠道试点。
3. Amazon FBA 标签/补仓资料半自动化。
4. eBay/TikTok Shop 订单 API。
5. 企业微信/邮件通知。
6. PDA/PWA 仓内扫码。
7. 多承运商规则引擎。

## 风险清单

| 风险 | 应对 |
| --- | --- |
| 库存账实不一致 | 所有库存变化写流水，余额可从流水重建 |
| 账单争议 | 每笔费用关联来源单据和操作日志 |
| 合规资料不完整 | KYC、VAT、EORI、FHDDS 审核状态前置 |
| 平台 API 复杂 | 第一版用 CSV/Excel，API 分阶段接入 |
| 英国快递面单差异大 | 先手动/半自动，选单渠道试点 |
| 退货识别困难 | 支持 tracking、原订单、收件人、SKU 模糊匹配 |
| 中文客服压力 | 异常中心、标准回复、照片留档、客户确认流 |

## 推荐里程碑

- W1-W2：原型确认、字段确认、报价规则确认。
- W3-W5：账号、客户、SKU、ASN、库存。
- W6-W8：订单、拣货、打包、出库。
- W9-W10：退货、FBA、异常。
- W11-W12：账单、权限、日志、导入导出。
- W13：试仓客户内测。
- W14：根据真实业务修正流程。
