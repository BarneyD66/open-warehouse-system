# 交付流程与 UI 设计简报

## 产品经理结论

参考店小秘、马帮 ERP、4PX 递四方、谷仓海外仓、万邑通 Winit 时，重点不是学习视觉，而是学习中国跨境卖家熟悉的交付流程。

网站和系统都要围绕一句话：

客户要随时知道“我现在在哪一步、还差什么资料、仓库会做什么、费用为什么产生、下一步点哪里”。

## 标准客户路径

1. 咨询/报价
   - 客户提交平台、品类、货量、服务需求。
   - 系统或客服输出适用服务、费用项、所需资料。

2. 开户/资料确认
   - 收集客户、店铺、VAT/EORI、商品品类、授权资料。

3. 商品建档
   - 先建 SKU，再入库。
   - 必须准备 SKU、品名、条码、图片、尺寸重量、申报信息。

4. 入库预报/ASN
   - 填运输方式、目的仓、箱数、SKU 明细。
   - 上传装箱单、箱唛、标签、物流追踪号。

5. 到仓验收/上架
   - 仓库核对预报、识别箱唛、登记差异、拍照异常、上架可售。

6. 订单履约
   - 订单导入后锁库、拣货、复核、包装、称重、面单、出库、轨迹回传。

7. 退货/FBA/异常
   - 退货按 RMA 或无 RMA 策略处理。
   - FBA 前置提醒 FNSKU、箱标、包装、超重、打托等要求。

8. 费用/对账
   - 费用关联入库单、订单、SKU、包裹、服务项目和计费规则。
   - 预估费用和实际账单要分开说明。

## 给 UI 的执行原则

- 首页只做判断入口：获取报价、创建入库预报、查看流程。
- 每个页面必须有一个最明显的下一步按钮。
- 服务页统一结构：适用场景、客户要准备什么、操作流程、状态说明、费用项、常见异常。
- 流程页做成向导：我还没合作、我已有货要入仓、我已有库存要出单、我有退货/FBA 需求。
- 入库预报做成步骤条：选择场景 -> 填商品箱规 -> 上传资料 -> 打印/确认标签 -> 提交审核。
- 移动端做“待我处理”，不要复制桌面表格。

## 入库预报页面应该解释什么

入库预报是仓库收货依据。仓库会按预报识别货物、核对数量、安排库位和上架；没有预报或标签不匹配，会影响收货和库存可售时间。

建议状态：

- 草稿
- 已提交
- 待预约
- 运输中
- 已到仓
- 验货中
- 异常待处理
- 已上架
- 已取消

## 订单履约页面应该解释什么

客户最关心四件事：

- 什么时候锁库存：订单创建或审核后锁库存。
- 什么时候扣费：称重出库或服务完成后形成费用。
- 什么时候有轨迹：承运商揽收后回传。
- 失败怎么办：地址异常、库存不足、面单失败、超尺寸、敏感品限制进入异常队列。

标准履约路径：

订单同步 -> 库存锁定 -> 选择渠道 -> 仓库拣货 -> 复核包装 -> 称重出库 -> 承运商揽收 -> 轨迹回传 -> 平台标记发货

## 退货和 FBA 页面应该解释什么

退货不是“退回就结束”。系统会先识别退件归属，再按商品状态和客户策略处理：可售上架、拍照暂存、换标重上架、销毁或转运。

FBA 补货路径：

备货到海外仓 -> 按 Amazon 要求贴 FNSKU/箱标/超重标 -> 创建 FBA 转运单 -> 仓库拣货换标/打托 -> 发往 Amazon 仓 -> 跟踪签收/异常

## 费用页面应该解释什么

费用页面不要只放价目表，要讲：

- 费用构成
- 计费时点
- 账单明细
- 异议处理

可用文案：

预估费用用于下单前决策，实际费用以仓库复核后的尺寸、重量、服务项和承运商账单为准。每笔费用都可追溯到订单号、入库单号、SKU、包裹号、服务项目和计费规则。

## UI 不要做什么

- 不做炫酷但无业务意义的大屏驾驶舱。
- 不做过多营销型模块。
- 不做桌面表格直接缩小到移动端。
- 不做一次性超长表单。
- 不做复杂筛选器和 BI 图表作为第一阶段重点。
- 不做万能工作台，客户、仓库、客服、财务视角要分清。

## 一句话标准

页面不是介绍公司能力，而是帮客户判断：我现在在哪一步、我要提交什么、仓库会做什么、什么时候能看到结果、费用为什么产生。
