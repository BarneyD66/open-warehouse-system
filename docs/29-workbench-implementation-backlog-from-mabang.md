# 工作台落地清单：马帮调研后的开发拆分

来源：`docs/28-mabang-workbench-research.md`  
用途：把马帮 ERP 中与我们项目相关的工作台、物流、海外仓管理能力，转成后续可开发的模块清单。

## 1. 产品边界

我们不做完整马帮，也不做通用跨境 ERP。我们的工作台应聚焦：

- 中国卖家的英国海外仓履约。
- 客户自助提交、查询和确认。
- 内部运营承接询价、入库、库存、出库、异常、费用。
- 后续逐步接入物流、第三方仓、平台和报表。

一句话定位：

> 让客户知道下一步要做什么，让运营知道今天要处理什么，让管理者知道哪里异常和哪里亏钱。

## 6. 异常中心

建议把异常中心做成跨模块视图，而不是散在各页面。

异常类型：

- 资料异常：缺装箱单、缺标签、缺追踪号、SKU 不清楚。
- 入库异常：未预约到仓、数量差异、破损、标签错误、无法识别。
- 库存异常：库存不足、库存为负、同步失败、库龄过长。
- 出库异常：地址错误、库存不足、面单失败、超时未发货。
- 物流异常：轨迹超时、投递失败、退回、丢件风险。
- 费用异常：重量差异、运费差异、未拉取费用、未确认账单。
- 接入异常：授权过期、接口失败、额度不足。

异常字段：

- 异常编号
- 关联对象类型
- 关联对象编号
- 客户
- 严重程度
- 当前负责人
- 客户是否可见
- 客户可见说明
- 内部处理备注
- 创建时间
- SLA 截止时间
- 状态

异常状态：

```text

open -> assigned -> waiting_customer -> processing -> resolved -> closed

```

## 9. UI 设计原则

- 客户端少字段、强引导、突出下一步。
- 内部后台高密度、强筛选、支持批量处理。
- 每个列表必须有空状态，不显示工程占位文案。
- 重要状态使用稳定颜色和标签，不只靠文字。
- 移动端不要照搬横向表格，改成队列卡片。
- 所有异常必须有负责人和下一步。
- 所有费用必须能追溯到订单、重量、渠道和确认状态。
