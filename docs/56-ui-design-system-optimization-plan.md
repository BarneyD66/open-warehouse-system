# 工作台 UI 设计系统优化方案

## 背景判断

这次参考的视频主题是“先搭建设计系统，再应用到项目页面”。结合当前工作台代码，问题不是单个页面没有样式，而是不同页面的视觉规则没有被统一执行：客户工作台、运营后台、仓库作业台、登录页都有各自的卡片、按钮、标签和布局写法，导致功能越来越完整后，界面显得有点散。

我们的系统是仓储和物流日常操作工具，不适合做成营销页式的大图、大卡片、大留白。更适合做成“高级但克制”的业务系统：信息密度高、层级清楚、状态醒目、操作路径短、移动端也能快速处理任务。

## 可以借鉴的核心方法

1. 先定义设计 Token，再写页面。
   颜色、字体、间距、圆角、阴影、边框、状态色、表单尺寸都要成为全站统一规则，而不是每个页面单独写 class。

2. 先做组件系统，再套业务模块。
   先沉淀按钮、状态标签、数据卡、表格、表单、步骤条、通知、空状态、操作栏、侧边导航，再把入库、库存、出库、物流、账单等页面套进去。

3. 页面按业务任务分组，而不是把所有模块平铺。
   客户端要先看到“我现在要处理什么”，再进入入库、库存、出库、物流、账单、工单。员工端要先看到异常、SLA、待审核、待作业，再进入具体模块。

4. 每个组件必须有状态。
   业务系统不能只有正常态，还要有空数据、加载、异常、成功、待处理、禁用、移动端压缩态、长文本溢出态。

5. 建立设计验收标准。
   每次改 UI 后，必须检查桌面端、移动端、中文长文案、下载文件中文、按钮点击、左侧导航跳转、空数据、异常数据。

## 当前项目主要问题

### 客户工作台

- 首页已经有内容，但信息仍偏“全部罗列”，客户第一次进来需要自己判断先点哪里。
- 快捷入口、指标卡、下一步建议、自助资料、工单、库存、退货等模块都存在，但视觉层级还不够强。
- 部分样式已经有 `portal-*` 设计系统类，但页面里仍混用大量一次性 Tailwind class，统一度不足。
- 移动端需要更明确的分段导航和底部主要操作，不然客户会觉得内容很多但不知道从哪开始。

### 运营后台

- 功能已经很多，但运营后台更需要“查得快”。当前模块数量变多后，左侧导航、锚点跳转、分组展示和保存视图要继续强化。
- 之前出现过左侧按钮点了没有跳转到指定区域的问题，说明导航和页面 section id / scroll margin 需要组件化治理。
- 少量接口导出文案存在乱码风险，例如审计日志导出标签，需要纳入全站中文质量检查。

### 仓库作业台

- 扫码、出库、采购到货、库位等功能已经逐步补齐，但视觉应该更像仓内 PDA/作业台：大输入框、清晰任务状态、成功/异常反馈、最近扫描记录、老板视角汇总。
- 仓库员工不需要看太多装饰，更需要“当前任务、下一扫什么、扫完结果、异常怎么处理”。

### 登录和官网入口

- 登录页视觉基础不错，有真实仓库背景和专属工作台文案，但需要和工作台内页的设计语言更统一。
- 登录、注册、忘记密码、账号资料这些账号体系页面要使用同一套表单组件。

## 建议建立的设计系统

### 1. 设计 Token

建议新增一层全站业务系统变量：

- 颜色：主色深青蓝、辅助青色、成功绿、提醒橙、异常红、中性灰。
- 背景：页面浅灰、面板白、弱提示底色、深色顶栏。
- 字号：页面标题、模块标题、表格标题、正文、辅助说明、标签。
- 间距：8 / 12 / 16 / 20 / 24 / 32。
- 圆角：卡片 8px，按钮 8px，标签 6px。
- 阴影：只保留 2-3 档，避免每个卡片阴影不同。
- 状态：待处理、处理中、待客户确认、已完成、异常、暂停。

### 2. 基础组件

优先做这些组件，后面所有页面复用：

- `WorkbenchShell`：客户端、运营端、仓库端统一壳。
- `SectionNav`：左侧/顶部模块导航，负责锚点、滚动定位和当前高亮。
- `PageHeader`：标题、说明、关键状态、主按钮。
- `MetricCard`：指标卡，统一图标、数字、趋势、说明。
- `ActionTile`：快捷入口卡，统一图标、标题、说明、右箭头。
- `StatusBadge`：所有状态统一中文、颜色和尺寸。
- `DataPanel`：业务面板，统一标题区、右侧操作、内容区。
- `DataTable`：列表、筛选、空状态、移动端卡片化。
- `FormField`：输入框、选择框、错误提示、说明文字统一。
- `Timeline`：入库、出库、物流、账单状态流转统一展示。
- `EmptyState`：没有数据时给下一步动作，而不是只显示“暂无”。

### 3. 业务页面模板

客户工作台建议拆成：

- 总览：待办、下一步建议、最近进度、异常提醒。
- 入库：入库预报、采购到货、资料补交、到仓/上架状态。
- 库存：SKU、库存余额、库龄、冻结/残次、库存流水、报表下载。
- 出库：出库申请、批量导入、拣货/发货进度、面单下载。
- 物流：轨迹、异常、签收证明、赔付/改派。
- 账单：费用明细、月结账单、争议、付款核销状态。
- 工单：售后、资料补充、物流异常、库存调整、入库差异。
- 账号：公司资料、VAT、EORI、店铺、密码和认证状态。

运营后台建议拆成：

- 今日总览：SLA、异常、待审核、待客户确认。
- 客户与询盘：客户资料、认证、报价、需求转入库。
- 入库与采购：预约、收货、上架、差异。
- 库存与库位：库区、库位、批次、冻结、盘点、移库。
- 出库与波次：订单、拣货、复核、称重、打印、交运。
- 物流闭环：渠道、面单、轨迹、异常、赔付。
- 费用账单：规则、月结、锁账、争议、核销。
- 权限审计：员工白名单、角色矩阵、操作日志、审批。

仓库作业台建议拆成：

- 扫码作业：当前任务、扫码输入、下一步提示、成功/异常反馈。
- 收货上架：采购/入库单、SKU 明细、已收/待收、已上架/待上架。
- 拣货复核：波次、拣货单、复核、称重、面单。
- 库位库存：库区、货架、库位容量、冻结、残次。
- 异常处理：少货、多货、破损、错 SKU、缺标签。
- 作业统计：员工今日扫描数、异常数、完成率、SLA。

## 优先级排期

### P0：先把视觉底座统一

- 新增设计 Token 和通用组件目录。
- 修复所有中文乱码和导出中文表头问题。
- 把状态标签、按钮、面板、指标卡统一成组件。
- 统一登录、客户工作台、运营后台、仓库作业台的页面背景和面板风格。

### P1：重做客户工作台总览

- 改成“任务优先”的总览，而不是纯模块罗列。
- 顶部突出客户编号、认证状态、待办数、最近异常。
- 快捷入口只保留最常用 4-6 个，其余进入分组页面。
- 客户端移动端增加顶部分段或底部导航。

### P2：重做运营后台导航和分组

- 左侧导航改为统一 `SectionNav`，点击必须准确滚到对应模块。
- 每个业务组有独立标题、说明、关键指标和筛选。
- 增加“保存视图 / 高级筛选 / 导出”统一工具栏。

### P3：强化仓库扫码作业体验

- 扫描后显示大号成功/异常反馈。
- 明确展示“下一步扫什么”。
- 老板视角增加今日扫描、异常、完成率和员工效率。
- 移动端/PDA 视图按钮更大、输入更清晰。

### P4：建立 UI 验收清单

- 桌面 1440 / 1280。
- 移动 390 / 430。
- 长中文文案不溢出。
- 左侧导航可跳转且当前项高亮。
- 所有导出文件中文。
- 空数据也有下一步动作。
- 关键按钮有成功/失败反馈。

## 建议下一步直接开发内容

第一轮不要全站大改，建议先做“客户工作台设计系统化改版”：

1. 新建通用 UI 组件和 token。
2. 重构 `/portal`，改成总览 + 分组入口 + 任务优先。
3. 把快捷入口、指标卡、下一步建议、自助资料、工单都换成统一组件。
4. 增加移动端分段导航。
5. 同步修复已发现的中文导出/乱码风险。

这样改完后，用户第一次登录会明显感觉更清晰、更高级；后续再把同一套组件推广到 `/ops` 和 `/warehouse`，成本会低很多。
