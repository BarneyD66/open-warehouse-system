# 询盘到正式报价工作流

## 目标

把官网询盘从“记录展示”升级为“客服可推进的报价队列”。客户提交询盘后，运营后台可以更新跟进状态、录入正式报价草稿，客户通过查进度或客户门户看到报价进展。

## 本轮实现

- `InquirySubmission.status` 从单一 `new` 扩展为状态流转。
- 新增 `InquiryQuoteDraft`，保存月度总报价、入库费、仓储费、出库费、退货费、FBA 费、增值服务费、报价说明和有效期。
- 新增 `PATCH /api/inquiries/[id]`，用于客服保存状态、报价草稿、下次跟进日期和备注。
- `/ops` 合作询盘卡片加入“报价跟进工作流”表单。
- `/tracking` 查询结果显示报价状态和正式报价草稿摘要。
- `/portal` 客户门户显示“报价待确认”和询盘当前状态。

## 询盘状态

| 状态 | 含义 |
| --- | --- |
| `new` | 新询盘，待方案评估 |
| `contacted` | 客服已联系客户 |
| `quoted` | 已生成正式报价草稿 |
| `waiting_customer` | 待客户确认报价或补充资料 |
| `converted_to_inbound` | 已转入入库预报 |
| `closed` | 已关闭 |

## 客服操作字段

| 字段 | 用途 |
| --- | --- |
| 跟进状态 | 推进询盘所处阶段 |
| 下次跟进日期 | 防止客户线索丢失 |
| 报价有效期 | 告诉客户报价窗口 |
| 月度总报价 GBP | 客服口径下的正式报价草稿 |
| 入库/仓储/出库/退货/FBA/增值服务费 | 拆分费用结构，便于客户理解 |
| 报价说明 | 说明报价边界和假设条件 |
| 客服跟进备注 | 内部记录沟通进展 |

## 验收标准

- 客服能在 `/ops` 保存询盘状态和正式报价草稿。
- 本地提交记录写入 `quoteDraft` 和 `followUpNote`。
- 客户用询盘编号查进度时看到“已生成报价草稿”。
- 客户门户出现“报价待确认”数量和报价待办。
- 移动端 `/ops` 无横向滚动。
