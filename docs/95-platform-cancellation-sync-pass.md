# 平台取消/作废订单复核闭环

## 本轮目标

平台订单 API 同步时，取消、作废、关闭订单不能被静默过滤。系统需要把这些订单单独沉淀到同步任务、运营后台和报表中，方便运营判断是否需要截单、取消面单、释放库存或联系客户。

## 已完成

- 平台网关新增 `cancelledOrders` 返回字段，成功拉单时会把 `cancelled`、`canceled`、`cancel`、`voided`、`closed` 以及带取消时间的订单识别为取消/作废订单。
- 有效订单仍然进入原有导入预检批次，取消/作废订单不会混入新出库单创建流程。
- 平台同步任务新增取消订单数量和明细，明细包含平台订单号、客户编号、原始状态、取消原因、取消时间。
- 同步任务会尝试按客户编号、平台、平台订单号和店铺名匹配本地出库单，匹配成功后记录出库单号和当前状态。
- 平台同步任务报表 `/api/ops/reports/platform-sync` 已改为干净中文导出，并新增“取消/作废订单数”“取消/作废订单明细”“下一步处理”。
- 运营后台最近同步记录新增黄色复核提示，发现平台取消/作废订单时直接展示订单号和匹配到的出库单。

## 产品策略

本轮先做“发现、记录、展示、导出、复核提醒”，暂不自动取消本地出库单或释放库存。原因是不同平台取消状态的触发时点、仓库作业进度、面单购买状态和客户沟通规则不同，生产环境应先由运营复核后再执行截单或取消面单，避免误操作。
