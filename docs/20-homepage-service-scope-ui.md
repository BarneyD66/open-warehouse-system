# 首页服务范围模块优化

## 背景

本轮根据客户反馈和竞品调研，首页需要更明确地告诉中国跨境卖家“服务包含什么”。参考方向来自谷仓服务页的服务分类方式，以及 4PX、万邑通、店小秘、马帮等项目常见的交付心智：客户不是先看系统术语，而是先判断自己属于哪个业务场景、需要准备什么、下一步点哪里。

## 产品判断

首页原有“服务能力”更像能力展示，信息不足以完成新客分流。因此本轮将该模块前移到“我现在处在哪一步？”行动入口之后，并升级为“服务包含什么”模块。

模块需要回答三件事：

- 这个服务适合什么卖家。
- 客户需要准备哪些资料或动作。
- 仓库会执行哪些处理，客户下一步应该点哪里。

## 首页服务分类

本轮首页展示 6 类服务：

| 服务 | 说明 | 主要入口 |
| --- | --- | --- |
| 到仓前协同 | 箱唛、装箱单、ETA、VAT/EORI、送仓预约 | `/inbound` |
| 英国海外仓储 | 收货验收、差异登记、库位上架、库存流水 | `/services` |
| 一件代发服务 | 多平台订单拣货、复核、打包、追踪回传 | `/workflow` |
| 尾程配送服务 | 英国本地承运商匹配、面单、交接、追踪 | `/tracking` |
| FBA 补仓中转 | FNSKU、箱标、换箱、打托、Amazon FC 发运 | `/inquiry?service=FBA%20Prep` |
| 退货与定制服务 | 退货识别、拍照质检、换标、重上架、销毁或转寄 | `/inquiry?service=Return%20%26%20Value-added` |

## UI 实现

- 新增 `ServiceScopeSection`。
- 每张服务卡包含图标、业务标签、服务说明、客户准备、仓库处理、流程标签和专属 CTA。
- 视觉采用白底服务矩阵、细色条、轻量图标和短标签，保持 SaaS 工作台感，不做廉价物流宣传页。
- 移动端为单列服务卡，避免横向滚动。

## 验收标准

- 首页首屏后能看到“服务包含什么”。
- 服务卡不使用空泛词，每张卡都出现具体业务对象，如箱唛、装箱单、SKU、追踪号、FBA、退货、费用事件。
- 每张服务卡都有明确下一步按钮，而不是统一“查看详情”。
- 390px 移动端服务卡无横向溢出，按钮和长文本不重叠。
