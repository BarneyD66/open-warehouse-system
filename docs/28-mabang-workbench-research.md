# 马帮 ERP 工作台调研记录

调研时间：2026-05-21  
调研方式：在已登录账号内进行只读页面观察、菜单悬停、列表页截图，不执行新增、保存、同步、开启授权等写入动作。  
调研目的：学习马帮 ERP 与我们“英国海外仓 / 工作台 / 后续物流”相关的信息架构、待办状态、列表字段和操作模型，为后续自研工作台设计提供参考。

## 1. 首页工作台结构

马帮首页不是单纯欢迎页，而是一个运营工作台。

核心组成：

- 顶部全局导航：`首页 / 开发 / 刊登 / 订单 / 商品 / 供应链 / 仓库 / 物流 / 客服 / 财务 / 报表 / 设置 / 云BI / 一盘货卖全球`。
- 左侧账户与快捷区：企业编号、剩余单量、专属顾问、常用功能、商品看板等。
- 主区待办事项：按业务域展示待处理数量，并带数据最近更新时间和“自定义待办事项”入口。
- 常用功能：`店铺授权 / 物流管理 / 订单管理 / 采购管理 / 商品管理 / 海外仓管理`。
- 待办事项按业务域拆分：订单、商品、采购、客服等，每个格子直接显示数量和异常/待办名称。

首页待办中已观察到的状态：

- 订单：即将签至到期待处理数、即将签至到期配货中数、WMS 剩余发签小于 1 天、同步失败数、交运异常数、待签结订单、待审核订单、待配封、待合并订单。
- 商品：库存同步异常。
- 采购：采购待审核、采购退货待审核、物流跟踪可用量、采购中、财务待审核、1688 授权异常、1688 账期即将到期。
- 客服：待处理 case、Amazon 待回复消息、Wish 待回复消息等。

对我们的启发：

- 工作台第一屏应优先服务“今天要处理什么”，不是只展示宣传或概览。
- 每个待办卡片要能落到一个明确队列，例如待报价、待补资料、待入库预约、待上架、待出库、物流异常、账单待确认。
- 待办数据需要显示刷新时间，避免运营误判数据是否实时。
- 支持用户自定义关注项，但默认要给出英国仓业务最重要的 P0 待办。

## 2. 常用功能入口

马帮的常用功能是首页左侧独立区，入口为：

- 店铺授权
- 物流管理
- 订单管理
- 采购管理
- 商品管理
- 海外仓管理

这说明高频运营动作不完全依赖顶部复杂菜单，而是从工作台直接进入。

对我们的启发：

- 我们工作台需要保留“常用入口”模块，优先放客户和仓库运营日常真正会点的功能。
- 建议第一版入口：
  - 客户询价
  - 报价审核
  - 入库预约
  - 库存查询
  - 出库订单
  - 物流追踪
  - 异常处理
  - 账单对账
- 后续可按角色定制：客户看到询价、入库、库存、出库、账单；内部运营看到队列、异常、成本、规则。

## 3. 物流模块学习

### 3.1 物流菜单结构

顶部“物流”下拉分为三组：

- 物流管理：物流授权、物流匹配规则、自定义运费、高仿标模板、运单号管理、地址管理、自定义运费（新）、企业申报信息管理。
- 增值服务：物流费用、物流跟踪、上传预报单、物流询价。
- 数据统计：物流统计。

左侧二级菜单也基本按同样结构组织：

- 物流管理：企业申报信息、物流授权、物流匹配规则、自定义运费、自定义运费（新）、高仿标模板、运单号管理、地址管理。
- 增值服务：物流费用、物流跟踪、上传预报单、物流询价。
- 数据统计：物流统计。

### 3.2 物流授权

页面结构：

- 顶部 tab：平台物流、自发物流、头程物流、三方/海外仓、云工厂、自定义物流。
- 筛选：物流类型、物流名称、授权状态。
- 列表：平台或服务商 logo、服务名称、授权指引、ON/OFF 授权状态。
- 页面动作：速卖通匹配本土物流授权、上传平台单号配置。

设计启发：

- 我们后续如果接第三方仓、承运商或平台 API，需要一个“接入健康”视图。
- 授权状态不应藏在设置里，应该进入工作台提醒，例如“Royal Mail 未授权”“三方仓 SKU 同步失败”“DPD 面单余额不足”。
- 授权页可用服务商卡片或列表，不一定照搬马帮的密集行，但必须显示状态、指引和可操作入口。

### 3.3 物流匹配规则

页面要点：

- 顶部提示：无渠道订单会每 20 分钟自动匹配一次；订单进入系统后 15 天内每天自动执行物流匹配；超过 15 天未匹配渠道的订单不再自动匹配，需要手动选择。
- 筛选：平台、店铺、物流渠道、仓库、状态、是否自动交运、优先级、更新时间、规则名称。
- 列表字段：优先级、规则名称、物流渠道、匹配方式、自动交运、状态、执行状态、时间。
- 动作：新增物流匹配规则、批量功能、设置不自动交运时间段。

设计启发：

- 我们应把“规则引擎”拆成可解释的运营规则，而不是黑盒自动派单。
- MVP 可以先做简版：按目的国家、重量、服务等级、客户、SKU 类型匹配物流方案。
- 规则必须有优先级、启停状态、最近执行结果和异常原因。

### 3.4 物流跟踪

页面结构：

- 顶部 tab：工作台、物流跟踪。
- 搜索维度：店铺、物流、目的国家、仓库、自定义分类、邮件发送成功/失败、订单编号批量搜索。
- 物流状态：全部、待查询、查询不到、运输中、到达待取、投递失败、可能异常、签收成功、轨迹超时、包裹退回、派送途中。
- 时间筛选：按妥投时间，支持 3/7/15/30/45/60 天内和日期区间。
- 运输天数筛选：全部、所有、3/7/15/30/45/60 天内、最小天数、最大天数。
- 辅助项：今日更新订单、今日未更新订单、剩余可跟踪单量、充值、跟踪设置、状态设置、状态说明。
- 表格字段：平台/店铺、订单号/交易号、目的国家/备注、时间、运输天数/停留天数/妥投天数、省理单号/物流方式、包裹状态、跟踪备注、操作。

设计启发：

- 物流跟踪很适合进入我们的工作台第一屏，尤其是“异常件”和“超时未更新件”。
- 状态建议分三层：
  - 正常：已发出、运输中、派送中、已签收。
  - 风险：多日未更新、清关停留、地址问题、待自提。
  - 异常：投递失败、退回、丢件、客户催件。
- 需要把“跟踪额度/接口可用量/更新时间”暴露出来，避免运营以为没有异常，实际是没有拉取。

### 3.5 物流费用

页面结构：

- 筛选：销售平台、店铺、物流渠道、订单编号、物流单号、交易号。
- 状态维度：运费拉取（全部/已支持/未支持）、是否拉取过、真实运费（有/无）、状态类型（未确认/已确认）、是否创建付款单。
- 时间：按发货时间。
- 动作：批量确认、批量提取运费、创建付款单、查看已支持的物流公司、导入/导出。
- 表格字段：发货日期/付款日期、店铺名称、订单编号/交易号/付款跟踪、物流渠道/物流跟踪号、预估运费/真实运费/物流运费、差异、物流重量/自称重、差异重量、状态、操作。

设计启发：

- 后续工作台不能只做到“发货完成”，还需要覆盖成本闭环。
- 物流费用建议拆成“预估费用、实际费用、差异、确认状态、付款/账单状态”。
- 对英国仓业务，最有价值的是费用差异预警：实际重量偏差、附加费、偏远费、退件费、头程分摊。

## 4. 海外仓管理学习

### 4.1 顶部仓库菜单

顶部“仓库”下拉展示：

- 仓库信息：仓库列表、仓位列表、手工出入库、库存盘点、分仓调拨、入/出库单。
- 组装加工：智能生成加工单、加工计划、加工列表、加工验货。
- 数据统计：加工统计、出入库流水。
- Amazon：MSKU 列表、FBA 订单、智能计算补货、补货计划、补货审核、发货计划、发货计划审核、FBA 货件、发货单、头程分摊。
- Wish：产品列表、订单列表、补货管理、调拨发货、补货计划（新）、调拨单管理、头程分摊（新）。
- Mercadolibre：产品列表、订单列表、调拨单管理、补货计划（新）等。

这说明马帮把“自有仓操作”和“平台海外仓/三方海外仓业务”分层处理。

### 4.2 海外仓左侧菜单

常用功能点击“海外仓管理”后进入海外仓产品列表，左侧结构为：

- 基础信息管理：产品列表、订单列表。
- 补货管理：智能计算补货、补货计划、调拨单管理、入/出库单、三方仓流水、三方仓流水相关项、头程分摊、补货计划、调拨发货、头程运费。

对我们的启发：

- 我们的英国仓工作台需要把“基础信息”和“运营单据”分开。
- 左侧导航可以围绕业务闭环组织：
  - 基础资料：客户、SKU、仓库、库位、渠道。
  - 入库：预约、到仓、验收、上架。
  - 库存：可用、锁定、在途、异常、库龄。
  - 出库：订单、拣货、打包、发货、跟踪。
  - 调拨/补货：补货建议、补货计划、调拨单。
  - 费用：仓租、操作费、物流费、差异。

### 4.3 海外仓产品列表

页面结构：

- 面包屑：基础信息管理 / 产品列表。
- 筛选：仓库、查询起始仓库存、开发员、销售员、配对状态、全部/海外仓 SKU 条件、批量关键词搜索。
- 动作：批量功能、配对本地 SKU、配对设置、列印商品标签、同步/更新 SKU、导出 Excel、海外仓 SKU 设置。
- 系统提示：需要确认已授权第三方海外仓，或查看海外仓 SKU 同步进度。
- 表格字段：缩略图、海外仓 SKU/产品名称/海外仓名称、库存 SKU/中文名/SKU 状态、销售员/开发员、7 天销量/28 天销量/日均销量、运输周期、起始仓库存量/起始仓库存占用量、可用/在途/在库、库龄/天、采购成本/重量、备注、操作。

设计启发：

- SKU 页面不是普通商品档案，而是“库存与销售表现结合页”。
- 我们后续 SKU 列表至少要有：
  - 客户 SKU、仓库 SKU、中文/英文品名、图片。
  - 可用库存、锁定库存、在途库存、异常库存。
  - 近 7/28 天出库量、日均出库、库龄。
  - 重量、体积、计费属性、采购/申报成本。
  - 同步状态、最近同步时间、异常原因。

### 4.4 海外仓订单列表

页面结构：

- 搜索内容：订单编号、交易号、买家 ID、买家姓名、内部单号、发货货运单号、商品编号、退货物流单号。
- 维度筛选：平台、店铺、服务商、仓库、状态。
- 状态：未发货、已发货。
- 动作：导出订单。
- 表格字段：商品信息/仓库、店铺/交易号、国家/买家信息、订单金额/订单利润、时间、自建物流、物流方式、操作。

设计启发：

- 出库订单队列需要强搜索能力，尤其是客户单号、平台单号、物流单号、SKU、退货单号。
- 我们可以先把状态拆成：待审核、待拣货、待打包、待发货、已发货、异常、已取消。
- 列表字段建议聚合展示：客户、订单号、目的地、SKU 数/件数、服务等级、截止发货时间、物流方式、费用、异常标签。

### 4.5 智能计算补货

页面结构：

- 筛选：仓库、状态、运输方式、建议补货、开始/结束日期、海外仓 SKU、批量搜索。
- 动作：创建补货计划、创建调拨单、设置仓库规则、商品规则、重新测算、导出、操作指引。
- 权限提示：看不到仓库数据时需要到员工列表的数据权限确认海外仓权限。
- 表格字段：缩略图、海外仓 SKU/名称、库存 SKU/名称、仓库、补货仓（实际/在途/预调入/未发货）、起始仓（实际/在途/未发货/采购计划）、推荐补货、补货量、7/14/28/42 销量、预计日均销量、操作。

设计启发：

- 补货建议要能解释，不只是给数量。
- 影响补货建议的字段包括：目标仓库存、起始仓库存、在途、未发货、采购计划、历史销量、运输周期。
- 我们的第一版可以做“建议补货提醒”，第二版再做自动创建调拨/补货计划。

### 4.6 补货计划

页面结构：

- 状态 tab：全部计划、审核中、未开始、计划中、已完结、已作废。
- 筛选：起始仓库、目的仓库、全部状态、审核状态、补货计划编号、海外仓 SKU、创建时间、创建人。
- 动作：批量处理、导出、打印中心、创建补货计划、操作指引。
- 表格字段：补货计划编号、补货计划状态、审核状态、补货计划进度、操作人、创建时间、仓库、备注、采购、操作。

设计启发：

- 补货计划本质是一个工单中心，状态要清晰。
- 我们可以将“补货计划”与“调拨单/入库预约”打通：建议 -> 计划 -> 调拨/采购 -> 到仓 -> 上架。

### 4.7 调拨单管理

页面结构：

- 状态 tab：全部状态、待发货、部分发货、已发货、部分签收、已签收、已作废、异常、已完结。
- 筛选：起始仓、目的仓、类型、状态、ERP 调拨单号、ERP 运输单号、海外仓 SKU、创建人、创建时间、调拨单备注。
- 动作：批量处理、创建调拨单、批量导入调拨单、导入/导出、操作指引。
- 表格字段：单号、单据类型、起始仓/目的仓、调拨单状态、调拨进度、创建人、时间、备注、物流信息、操作。

设计启发：

- 调拨是典型跨仓履约流程，要能看到发货、在途、签收、异常、完结。
- 工作台应提供“在途调拨”和“异常调拨”两个高优先级队列。

### 4.8 入/出库单

页面结构：

- tab：入库单列表、出库单列表。
- 筛选：目的仓、状态、全部类型、创建时间、创建人、三方仓入库单号、三方仓 SKU。
- 动作：批量操作、导入/导出、打印中心、批量维护头程费。
- 设置：入/出库单设置。
- 表格字段：单号、单据类型/中转状态、单据状态、仓库、SKU 信息、物流信息、头程费、创建人、操作。

设计启发：

- 入库和出库可以共享一套单据框架，但状态和关键动作不同。
- 入库要重点看预约、到仓、验收、差异、上架；出库要重点看拣货、复核、打包、交运、跟踪。
- 头程费是跨境仓很重要的成本字段，不能只放在财务后处理。

## 5. 报表、财务、设置补充观察

报表菜单覆盖：

- 销售报告：收支报表、营业额报表、订单状态报表、退款报表、商品销量报表、订单分析、Listing 实时销量、库存实时销量、组合实时销量。
- 财务报告：利润报表（新）、费用管理（新）、业务配置（新）。
- 商品报告：进销存报表（新）、库龄分析、海外仓库存对账。
- 客服报告：客服报表。
- 亚马逊报告：货件移除报告、物流赔偿报告、移除订单详细报告、退货报告、库存幅点报告、报告下载。

- 参数设置：审批规则设置、速卖通买家自选物流、订单发货期限设置、订单异常分类处理配置、物流优先级设置、地址映射配置、别名管理。

客服菜单补充：

- Ebay：消息列表、Ebay Case、Ebay 中差评、自动群发规则、消息自动回复、取消订单申请。

- 通用服务：客户列表、快捷短语设置、消息分配规则、消息/邮件模板。
- 马帮聊聊：Shopee、Lazada、Tiktokshop、MercadoLibre、OZON、Allegro 消息和自动回复。

- 海外仓库存对账：按父仓、快照时间、SKU 和对账状态筛选；动作包括导出、立即对账、对账设置；字段包括父仓名称、库存 SKU、库存对比结果、库存差值、父仓总库存、子仓总库存、快照时间。

审批规则页补充：

- 筛选：全部状态、全部单据类型、规则名称。
- 动作：搜索、新增规则。
- 表格字段：优先级、规则名称、类型、备注、状态、创建人员、时间、操作。
- 提示规则：优先级先按最高级匹配，优先级相同时按创建时间排序，时间越早优先级越高。

订单异常分类处理配置补充：

- 页面说明：灰色代表无异常，红色代表异常未处理，绿色代表异常已处理。

- 动作：添加物流渠道、批量删除、更新订单优先级、保存；调研中未执行这些动作。

订单发货期限设置补充：

- 用于根据平台发货期限和订单付款时间计算订单剩余发货时间。
- 当前支持平台包括 Aliexpress、Amazon、Wish、Joom、eBay、Walmart、Shopify、MercadoLibre、Lazada、Shopee、TikTok 等。
- 页面包含“发货到期提醒”，可设置提前多少小时提醒，观察到默认值为 48 小时。
- 包含“各平台发货期限”区域和“虚假发货订单显示剩余发货时间”开关。
- 页面底部有保存动作，调研中未执行保存。

地址映射配置补充：

- 可开启地址映射自动转换。
- 筛选条件：平台、国家、地址字段类型、检索文本。
- 表格字段：序号、平台、国家、地址类型、平台原始信息、转换后地址信息。
- 观察到示例：Shopify 日本省/州字段，将 Kyoto、Hyogo、Kanagawa、Tokyo、Osaka 等原始平台文本映射为京都府、兵库县、神奈川县、东京都、大阪府等标准中文地址。
- 对物流分单、面单校验、异常地址识别很关键。

别名管理补充：

- 页签：Store Alias、Warehouse Alias、Custom Category Alias。
- 支持按对象名称搜索，支持语言筛选，动作包括 Batch Modify Aliases、Import excel。
- 表格字段覆盖多语言列：English、Chinese、Spanish、Indonesian、Thai、Russian、Portuguese 等。
- 说明马帮会区分内部对象名和不同语言/场景的展示别名。

导入/导出任务补充：

- 页签：导入任务、导出任务。
- 字段：文件名称、任务类型、开始时间、完成时间、操作人、进度、总行数、成功数、失败数、操作。
- 适合作为批量导入、导出报表、失败文件下载、重试的异步任务模型参考。

任务列表补充：

- 页签：任务创建、任务执行。
- 搜索维度：标题、执行人、任务对象、单据编号。
- 筛选：紧急程度、任务状态、创建/完成时间。
- 状态：未执行、执行中、已完成、执行失败、已删除。
- 表格字段：单据编号、任务标题、分类、任务对象、紧急程度、创建人/执行人、创建时间/完成时间、状态、操作。

任务中心补充：

- 页签：Export、Import、Recalculate。
- 筛选：Status、Operator、Addition Time、日期区间、Report Name。
- 表格字段：Task Name、Addition Time、Generation Time、Type、Status、Operator、Operation。
- 更偏报表/财务类异步计算任务，可和导入导出任务中心统一抽象。

对我们的启发：

- 数据报表、权限、任务中心、导入导出任务要提前留结构位。
- 即便 MVP 不做复杂财务，也应保留费用和账单的闭环字段。
- 设置不应成为所有配置的垃圾桶，业务规则需要能从对应工作台页面进入。
- 客服入口说明后续工作台不能只面向仓库，还要预留客户消息、评价、Case 和消息分配规则的聚合入口。
- 报表中心需要先把库存分桶、库存流水、费用差异和对账结果的数据口径定清楚，再做图表。
- 审批规则本质上是跨单据的规则引擎，待办卡片要能解释“为什么需要我审核”。
- 异常中心应支持按客户或业务域配置异常开关、阈值、排除条件和默认处理人。
- 物流渠道选择不仅是匹配规则，还存在平台买家自选物流和内部优先级的冲突，需要记录渠道来源和最终采用原因。
- 平台发货期限、客户内部 SLA 和物流时效需要统一成“剩余处理时间/超时风险”的工作台字段。
- 地址映射和别名管理说明基础配置会直接影响订单、物流、报表的可读性，不能只当成后台小功能。
- 异步任务中心应该成为导入、导出、重算、报表生成的统一底座，并纳入失败提醒。

## 6. 仓库基础模块补充学习

这部分来自顶部“仓库”菜单下的自有仓基础能力，与“海外仓管理”不同，更偏 WMS 底座。

### 6.1 仓库列表

页面结构：

- 筛选：仓库名称、仓库属性。
- 仓库属性：自建本地仓、自建第三方海外仓、第三方、FBA、平台仓。
- 动作：新增仓库、导出 Excel、订单仓库匹配规则、批量仓库设置、仓库设置。
- 系统提示：库存种类、库存总量、库存货值、在途货值每 30 分钟自动计算一次，并展示最近更新时间，也支持手动更新。
- 表格字段：名称、属性、供货商、国家、货架数、库存种类、库存总量、库存货值、在途货值、默认仓库、是否允许负库存、状态、备注、操作。
- 行内入口：库存明细、库存清零、货值明细、修改仓库名称。

设计启发：

- 仓库不是简单枚举，至少需要区分自建仓、第三方仓、FBA/平台仓。
- 库存统计要展示最近计算时间，且需要可重算。
- 是否允许负库存、默认仓库、仓库匹配规则都属于会影响业务结果的关键配置，应进入权限控制和审计。

### 6.2 仓位列表

页面结构：

- 视图名称：Product grid chart。
- 状态 tab：All、Occupied、Recyclable、Available。
- 筛选：Warehouse、Shelf、Shelf specifications、Grid position number。
- 页面以库位网格为核心，支持按仓库、货架、货架规格和库位编号定位。

设计启发：

- 做到仓内作业时，库存不能只停留在 SKU 维度，要下钻到库位。
- 库位状态至少要有可用、占用、可回收。
- 移动端扫码作业时，库位编号和 SKU 绑定必须清楚。

### 6.3 手工出入库

页面结构：

- tab：审核、手工入库、手工出库。
- 搜索：批次号、库存 SKU 编号、仓位、备注、操作人。
- 状态：新入库单/新出库单、待提交、等待入库/等待出库、已完成、已作废。
- 转 WMS 状态：无需转入、未转 WMS、已转 WMS、取消 WMS 入库/出库。
- 来源：开放平台 API、TMS、手工新增、模板导入、WMS、库存 SKU。
- 其他筛选：仓库、入库/出库类型、时间。
- 动作：批量操作、审批流程设置、导入/导出相关、新增入库批次/新增出库批次。
- 表格字段：批次编号、仓库、入库/出库类型、备注、SKU 个数/箱数、转 WMS 状态、状态、创建时间/真实入库或出库时间、审核人/操作人、操作。

设计启发：

- 手工出入库是库存修正和特殊业务入口，必须有审批和来源。
- 手工操作要记录真实发生时间，不能只记录创建时间。
- 后续我们做库存调整时，要区分“业务单据驱动”和“手工修正驱动”。

### 6.4 库存盘点

页面结构：

- 搜索：批次号、库存 SKU 编号、仓位、备注、操作人。
- 状态：全部、Unpassed、Processed、Completed、待提交、已作废。
- 筛选：仓库、时间。
- 动作：批量功能、盘点任务、新增盘点、导出、显示盘点商品详情。
- 表格字段：批次编号、仓库、备注、SKU 个数、状态、盘点日期、操作人、审批人、操作。

设计启发：

- 库存盘点不是简单改库存，而是有批次、有审批、有任务的库存校准流程。
- 后续盘点要能追踪盘点前数量、盘点后数量、差异、审批人和原因。

### 6.5 分仓调拨

页面结构：

- 顶部提示：分仓调拨单商品的体积、重量、货值可支持设置自动更新。
- tab：分仓调拨审核、仓库调拨发货、仓库调拨签收、转 WMS 发货。
- 搜索：批次号、库存 SKU 编号、主 SKU、货运单号、起始仓位、目标仓位、发货人、备注。
- 状态：全部、新调拨、待发货、待签收、部分签收、已签收、签收异常、已作废。
- 动作：排序、审批流程设置、添加/导出、批量操作、显示调拨商品详情、调拨设置。
- 表格字段：批次编号、起始仓库/目标仓库、发货备注/签收备注、状态/自定义分类、创建日期、创建人、期望发货日期/发货日期/期望到货时间、最近签收日期/签收人、物流渠道/运输方式、总重量/总体积/总货值、分摊方式/运费、审核人、操作。

设计启发：

- 分仓调拨是比普通出库更复杂的跨仓流程，需要发货和签收两个阶段。
- 调拨要天然支持部分签收和签收异常。
- 重量、体积、货值、运费和分摊方式要在调拨单上保留，方便后续成本归集。

### 6.6 通用入/出库单

页面结构：

- tab：入库单列表、出库单列表。
- 筛选：目的仓、状态、全部类型、创建时间、创建人、三方仓入库单号、三方仓 SKU。
- 动作：批量操作、导入/导出、打印中心、批量维护头程费、入/出库单设置。
- 表格字段：单号、单据类型/中转状态、单据状态、仓库、SKU 信息、物流信息、头程费、创建人、操作。

设计启发：

- 入库/出库单是基础单据框架，可以承载三方仓和自有仓的不同业务。
- 头程费不是财务后置字段，而是从入/出库单阶段就要记录。

### 6.7 出入库流水

页面结构：

- 筛选：店铺、日期、库存 SKU、入库/出库类型、出入库方式、仓库、操作员、供应商。
- 类型：入库、出库。
- 出入库方式覆盖：采购入库、分仓调拨入库、分仓调拨作废入库、分仓调拨签收入库、手工入库、订单退货入库、加工商品入库、手工退原材料入库、退原未使用原材料入库、海外仓入库、FBA 货件库存返还、盘点、快速调整库存、WMS 盘点、WMS 退货入库、WMS 手工入库、WMS 快速调整、平台仓调拨入库、TMS 手工入库等。
- 表格字段：日期、库存 SKU、名称、仓库、入库数量、出库数量、库存、总成本。
- 底部合计：入库总量、出库总量、累计总成本。

设计启发：

- 出入库流水是库存可信度的底账，所有库存变化都要能追溯来源。
- 后续必须把库存余额和库存流水分开建模：余额用于当前查询，流水用于审计和复盘。
- 出入库方式是重要枚举，需要覆盖业务来源、系统来源和人工来源。

表格字段：

- 缩略图、库存 SKU 编号、中文名称/英文名称。
- 父级仓库、仓库、仓位。

- 搜索维度：库存 SKU、虚拟 SKU、中文名称、英文名称、原厂 SKU、原材料 SKU、默认供应商、主 SKU、NCM 等。

- 动作：批量功能、更多功能、列印中心、图片管理、排序、数据刷新、导入商品目录、添加/导出。

设计启发：

- 主 SKU 适合商品主档和销量分析，库存 SKU 才是仓库库存、供应商、重量、加工/赠品等履约字段的核心。
- 库存查询应作为工作台高频入口，支持库存、在途、警戒量、销量和成本在同一视图里对照。
- 库龄分析应成为库存异常的一部分，不只是报表。

### 8.6 包装验货

页面形态：

- 更像仓内扫码工作台，而不是普通管理列表。

输入项：

- 扫描订单编号、货运单号或交易号。

可选项：

右上角入口：

- 操作日志、打印机设置、验货设置。

设计启发：

- 出库作业需要独立的扫码界面，不能让仓内人员使用高密度订单列表。
- 验货、打印、发货可以串成一个可配置流程，但必须谨慎处理自动发货。

## 10. 对我们工作台的推荐信息架构

建议后续工作台采用“角色首页 + 业务队列 + 规则/配置”的结构。

### 10.1 首页

- 今日待办：待报价、待客户补资料、待入库预约确认、待到仓验收、待上架、待出库、物流异常、账单待确认。
- 异常看板：库存差异、物流超时、入库差异、出库失败、费用差异、授权/同步失败。
- 快捷入口：新建询价、创建入库、库存查询、创建出库、物流追踪、查看账单。
- 数据更新时间：所有队列显示最近刷新时间。

### 10.2 海外仓模块

- SKU 库存：SKU、库存、库龄、近 7/28 天出库、同步状态。
- 入库单：预约、到仓、验收、上架、差异。
- 出库单：审核、拣货、打包、发货、跟踪。
- 调拨/补货：补货建议、补货计划、调拨单、在途、签收。
- 第三方仓流水：库存变动、出入库记录、同步差异。
- 成本：头程费、仓租、操作费、物流费。

### 10.3 物流模块

- 物流授权：服务商接入状态、异常、指引。
- 物流规则：渠道匹配、优先级、自动交运、执行结果。
- 物流跟踪：状态队列、超时、异常、妥投。
- 物流费用：预估、实际、差异、确认、付款单。
- 物流统计：发货量、时效、异常率、费用差异。

## 11. 不建议直接照搬的地方

- 马帮功能非常全，但对我们当前阶段过重；第一版不要做过深的平台矩阵。
- 许多页面字段密度很高，适合资深 ERP 用户；我们的客户入口需要更少字段、更强引导。
- `el.table.emptyText` 一类空状态暴露了工程占位文本，我们自研时要做好空态文案。
- 列表页横向滚动很常见，桌面可接受，但移动端必须重新设计卡片式队列。
- 导入导出、批量处理、打印中心很重要，但应分阶段上线。

## 12. 下一步可落地拆解

P0：

- 工作台待办模型：报价、资料、入库、出库、物流、账单。
- 海外仓 SKU 库存表：可用、锁定、在途、库龄、同步状态。
- 出库订单队列：客户单号、目的地、物流方式、状态、异常。
- 物流跟踪队列：运输中、超时、投递失败、退回、已签收。

P1：

- 入库预约/验收/上架工单。
- 物流费用核对：预估 vs 实际。
- 补货建议：按销量和库存天数给提醒。
- 权限与接入健康：仓库权限、承运商授权、同步失败。
- 仓库基础设置：仓库、库位、库存流水。
- 手工出入库与盘点审批。

P2：

- 物流匹配规则。
- 调拨单管理。
- 补货计划与审核流。
- 报表中心：库存、库龄、物流时效、费用差异。
- 分仓调拨、成本分摊和库存审计增强。
