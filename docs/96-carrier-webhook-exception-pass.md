# 承运商轨迹异常自动处理闭环

## 本轮目标

真实承运商 API 闭环不仅要能买面单、取消面单和接收轨迹，还要在派送失败、地址错误、客户不在、破损、丢件、退回等异常发生时自动进入运营和客户可处理的流程。

## 已完成

- 承运商 webhook `/api/webhooks/carriers/[provider]` 已替换为干净中文实现，保留 HMAC 签名校验、旧版密钥校验、防重放和轨迹自动回传。
- webhook 正常轨迹仍会写入出库单轨迹，并根据状态更新出库单为已交接、运输中、派送中、已签收或异常阻塞。
- 当承运商回传 `exception`、`fail`、`return` 等异常状态时，系统会自动创建物流异常处理记录。
- 异常类型会根据回传内容自动归类为派送失败、地址问题、客户不在、破损、丢件、退回、赔付等。
- webhook 可接收改派要求、改派说明、签收证明链接、赔付金额和赔付说明，并写入异常记录。
- 自动创建的异常会同步生成客户工单，客户和运营都可以在工作台内继续确认、沟通或处理赔付。

## 产品策略

这一轮把“承运商异常回传”从单纯轨迹状态升级为可处理任务。真实 Royal Mail、DPD、Evri 等接口接入后，只要回传字段映射到当前 webhook 格式，就能自动进入同一套异常、工单、赔付和客户确认闭环。
