# 49. 操作日志检索与持久化

## 已完成
- 审计日志支持 Postgres 持久化：配置 `POSTGRES_URL` 或 `DATABASE_URL` 后，关键操作会写入 `warehouse_audit_logs`，避免生产环境临时文件丢失。
- 本地无数据库时仍保留 `.local-data/audit-logs.json` 作为开发兜底。
- 运营后台新增“审计”模块，可按关键词、操作人类型、业务类型和动作筛选日志。
- 日志列表展示时间、动作、操作人、关联对象、客户编号、说明和操作后摘要。
- 运营后台审计模块新增“导出当前筛选”和“导出全部日志”，导出 CSV 使用中文文件名、中文表头和中文角色/业务类型说明。
- 新增 `/api/ops/audit-logs` 服务端导出接口，支持 `customerCode`、`action`、`actorRole`、`targetType`、`targetId`、`keyword`、`dateFrom`、`dateTo` 和 `limit` 筛选，便于按客户、日期或单号归档。
- 客户账号暂停/恢复已经纳入敏感操作控制：后端会校验角色权限，强制填写暂停/恢复原因；若该角色配置了“敏感操作需要二次确认”，还必须输入客户编号确认。
- 客户审核前端同步改为显式确认，不再用一键模板理由直接暂停或恢复账号。

## 产品价值
- 对标马帮的操作追溯能力，库存调整、扫码、出入库、物流异常和客户账号动作都能集中查看。
- 老板和运营能快速回答“谁在什么时候改了什么”，减少库存差异、账单争议和异常处理时的反复查聊天记录。
- 为后续扩展更多敏感操作二次确认、审批流复盘、员工绩效和异常责任归因打基础。
